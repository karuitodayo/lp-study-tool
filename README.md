# LP制作教科書（自分用 制作サポートツール）

LP（ランディングページ）制作を学びながら進めるための、個人用のローカルWebアプリです。
利用者（あなた）がLPを設計・ワイヤーフレーム作成・コーディングしながら理解していくための「教科書」を提供します。

- 実装したのはClaude Code（AI）です。このツールを使ってLPを制作するのは利用者自身です。
- 画像分析は、外部のAI API（Gemini／Claude API／OpenAI等）を**接続せず**、Claude Codeセッション自身が画像を直接読み取って行う方式を採用しています。アプリ内に「自動で分析するボタン」はなく、利用者がClaude Codeに「画像を分析してください」のように依頼するたびに、Claude Codeが結果を保存します。
- ①設計の下書き・②ワイヤーフレームのテンプレート生成（画像分析を使わないもの）は、入力内容を定型文に当てはめているだけで、AIによる分析・提案ではありません。該当箇所には「サンプル」「テンプレート」と明示しています。

## 使用技術

| 分類 | 技術 |
|---|---|
| フロントエンド | React 18 / TypeScript / Vite |
| バックエンド | Node.js / Express / multer（画像アップロード） |
| 画像分析（任意・要APIキー） | Gemini API |
| 教材生成・相談欄 | ローカルのClaude Code CLI（`claude -p`）をサブプロセスとして呼び出し |
| データ保存 | サーバー側のJSONファイル（`server/data/projects/`、データベース不使用） |

## 起動方法（Windows）

初回のみ依存パッケージをインストールします。

```powershell
cd "C:\Users\krklu\Desktop\WEBサイトサポートツール"
npm install
```

起動（API サーバーと画面を同時に起動）：

```powershell
npm run dev
```

ブラウザで以下を開いてください。

**http://localhost:5173/**

- APIサーバーは `http://127.0.0.1:4000` で起動し、**自分のPCからのみ**アクセスできます（外部公開はしていません）。
- 終了するときはターミナルで `Ctrl+C` を押してください。

個別に起動したい場合：

```powershell
npm run dev:server   # APIサーバーのみ（ポート4000）
npm run dev:web      # 画面のみ（ポート5173）
```

## 必要な設定

- 基本機能（プロジェクト管理・画像登録・設計・ワイヤーフレーム・実装教材・相談欄）にAPIキーは不要です。
- **画像分析をGemini APIで自動化する場合のみ**、APIキーの設定が必要です（任意・無料枠で利用可能）。
  1. https://aistudio.google.com/apikey でAPIキーを取得する（クレジットカード登録不要）。
  2. `server/.env.example` をコピーして `server/.env` を作成済みの場合はそれを、まだなら新しく `server/.env` を作成し、`GEMINI_API_KEY=` の後ろにキーを貼り付ける。
  3. サーバーを再起動する（`npm run dev`をやり直す）。
  - `server/.env` はGit管理対象外で、画面やログにも出力されません。未設定のままでも他の機能は通常どおり使えます。
  - 使用モデルは`GEMINI_MODEL`で変更できます（省略時は`gemini-3.8-flash`）。

## 画面構成

1. **プロジェクト一覧／新規作成**：プロジェクト名と制作条件（未定可）を入力して作成します。
2. **画像登録**：完成イメージ画像（1枚）と参考画像（複数・メモ・参考範囲のドラッグ指定）を登録します。
3. **画像分析**：構成・配置の分析結果を表示します。「画像を分析する」ボタンでGemini APIに自動分析させるか（要APIキー設定）、Claude Codeに「登録画像を分析してください」のように依頼すると、Claude Codeが画像を直接読み取って結果をここに保存します。画像を複数の区画に分け、区画ごとのラベル・配置パターン・気づいた点を確認・修正し、内容を確定できます。
4. **①設計**：目的・ターゲット・課題・商品・CTAなどの入力、案件の依頼文の保管、入力内容を定型文に当てはめた下書き整理（テンプレート）、内容の確定。
5. **②ワイヤーフレーム**：「画像分析の結果から生成する」（実際に分析した構成・配置を反映）、または「設計の内容から生成する」「完成イメージ画像から構成案を起こす」（定番構成のテンプレート）のいずれかでセクション案を作成。白黒の簡易図で見出し・文章・画像・ボタンの配置を示し、各セクションの役割・順番の理由を表示。見出し・本文・配置・ボタンは自由に編集、並び替え・追加・削除が可能。
6. **④実装教材**：プロジェクト専用の教材があればそれを表示します。まだない場合は、無関係な共通サンプルを表示する代わりに「まだ教材がありません」という案内と「教材を作成する」ボタンを表示します。ボタンから、登録済みの完成イメージ画像・確定済みの画像分析・①設計をもとに、既存のClaude Code CLI接続でこのプロジェクト専用の教材（ファイルの準備から一手順ずつ）を自動生成・保存できます（要：完成イメージ画像の登録、画像分析の確定）。各手順は「A.今回作るところ→B.図と説明（親子関係・採用CSSの理由）→C.どこに書くか（ファイル・操作種別）→D.差分コード→E.段階別プレビュー→F.調整と確認」の構成で、「次へ」で順に進みます（スキップ不可、後戻り可）。コードのコピー、段階別プレビュー、進捗保存に対応。画像分析・ワイヤーフレームが教材作成後に変更されると「見直しが必要」と案内します。各手順には「相談で修正する」欄があり、Claude Codeが変更案を作成しますが、「適用する」を押すまで教材は書き換わりません。教材全体の「作り直す」もできます（上書き前に確認）。
7. **自分のコードを試す**：自分で書いたHTML/CSSを貼り付けて、隔離されたiframe内で表示確認できます。
8. **相談欄**：画面を移動せずに、プロジェクトの制作についてClaude Codeへ相談できます。質問・送信・回答表示・処理中表示・失敗時の案内に対応。設定変更や教材データの更新はここでは行わず、回答は提案として示されます。

## 実装済み範囲（今回まで）

- プロジェクトの作成・一覧・削除、サーバー側JSONファイルへの自動保存と再起動後の復元
- 画像登録（完成イメージ・参考画像、メモ、ドラッグによる参考範囲指定）。画像形式（JPEG/PNG/WebP/GIF）・容量（8MB）の検証とエラー時の日本語案内
- **画像分析**：次の2方式で保存できる。
  - Claude Codeが登録画像を直接読み取り、画像を複数の区画（ヘッダー／ヒーロー／グリッド等）に分け、区画ごとの位置・配置パターン・役割の手がかり・気づいた点・画像内に実際に見えた文字（参考用）を記録する方式（外部AI API不使用）。
  - **Gemini API（任意・要APIキー設定）**：「画像を分析する」ボタンから、登録済みの完成イメージ画像をサーバーがGemini APIへ送信し、同じ形式（区画の順序・ラベル・配置パターン・見出し数/画像有無/ボタン有無/列数・観測した文字・配色/文字/余白の傾向・HTML/CSSの組み立て方針）で結果を得る。保存前に既存の分析内容を上書きしてよいか確認し、取得に失敗した場合は既存データをそのまま残す。二重送信防止（処理中は409）・60秒タイムアウト・キー未設定／無効・利用上限・通信失敗を区別した案内に対応。自動再試行はしない。
  - どちらの方式で保存した結果も、アプリ側の画面で確認・修正・確定でき、同じデータとして②ワイヤーフレーム・相談欄・教材作成から参照される。
- **①設計**：構造化された入力項目、案件依頼文の保管、入力内容を定型文に当てはめた下書き生成（不足項目の指摘を含む）、内容の確定／確定解除
- **②ワイヤーフレーム**：
  - 「画像分析の結果から生成する」：確定した画像分析から、区画数・配置パターン・順序をそのまま反映してセクション案を作成（見出し・本文・ボタン文言は①設計の内容から組み立て、画像内の文字はそのまま転記しない）
  - 「設計の内容から生成する」「完成イメージ画像から構成案を起こす」：定番構成のテンプレート（従来どおり）
  - 白黒の配置図（中央寄せ／画像左右／グリッド／縦並びリスト／ヘッダーの6パターン）、セクションの役割・理由の表示、見出し・本文・配置パターン・ボタンの編集、並び替え（上下移動）、追加・削除、保存
- **④実装教材**：プロジェクト専用教材の保存・表示（`project.material`）。手順移動（次へ／前へ、スキップ不可）、お手本画像への図解オーバーレイ（比率を保ったまま拡大縮小に追従）、親子関係・採用CSSの理由を示す構造図、差分コード表示（追加行の強調）、コピー機能（行番号・差分記号なし、クリップボードAPI失敗時は代替手段で表示）、手順ごとの段階別プレビュー（隔離iframe）、調整ポイントと「表示が違うときにまず見る場所」の案内。画像分析・ワイヤーフレーム変更時の見直し案内（作成時のタイムスタンプとの比較）。プロジェクト専用教材がない場合は、共通サンプルへフォールバックせず「教材を作成する」ボタンを表示する。
- **④実装教材の生成（Claude Code CLI経由）**：「教材を作成する」から、登録済みの完成イメージ画像・確定済みの画像分析・①設計をもとに、既存のClaude Code CLI接続（相談欄と同じ非対話モード・最小権限、画像添付）でプロジェクト専用教材（手順一式のJSON）を生成する。結果はいったん提案として返し、画面側で保存する（既存教材がある場合は上書き前に確認）。登録済みの実装用素材（写真）は、素材名と一致するキーのphotoSlotとして教材に組み込まれ、既存の素材差し込み（`materialAssets.ts`）の仕組みでコード・プレビューに反映される。二重送信防止・8分タイムアウト・CLI未検出／未ログイン／利用上限／応答読み取り失敗を区別した案内に対応。失敗時は既存の教材データに触れない。
- **教材の手順を相談で修正**：各手順に修正依頼欄があり、Claude Codeが変更案（説明文・差分コード・累積プレビュー）を提案として表示する。相談しただけでは教材は書き換わらず、「この内容を適用する」を押した手順だけがその場で教材とプレビューに反映される（他の手順には影響しない）。
- 自分のコードを試すプレビュー（隔離iframe）
- **相談欄**：サーバー（Node.js/Express）からPC内のClaude Code CLI（`claude -p`、非対話モード）をサブスクリプション（OAuthログイン）のまま呼び出す。質問文は引数ではなく標準入力（stream-json形式）で渡し、シェル文字列への連結はしない。ツールは`Skill`のみを許可し、ファイル編集・コマンド実行・Web取得等は一切許可しない（MCPサーバーも`--strict-mcp-config`で無効化）。完成イメージ画像は、サーバーがあらかじめ読み込んでbase64の画像ブロックとして会話に添付する方式を採用（Claude Code自身にファイルシステムを探索させない）。これは、ファイルアクセスを許可ディレクトリに限定する`--restricted`/`--add-dir`オプションを検証した際、実際には許可ディレクトリ外のファイルも読めてしまう挙動を確認したため。渡す情報は①設計・確定済み画像分析・②ワイヤーフレーム・教材作成ルール（LP-TEXTBOOK-RULES.md）・直近10件の相談履歴。会話履歴はプロジェクトのproject.jsonに保存し、他プロジェクトと混在しない。二重送信はプロジェクト単位のロックで防止（処理中は409を返す）。タイムアウトは2分。CLI未検出／未ログイン／利用上限／タイムアウト／その他失敗を区別して案内し、自動再試行は行わない。APIキー課金への切り替えは行わず、環境にANTHROPIC_API_KEYがあってもこの機能の呼び出しには渡さない。

### KOMOREBIプロジェクトでの検証内容（ヘッダー＋ファーストビュー）

実在する登録画像（カフェ「KOMOREBI」の完成イメージ）をもとに、Claude Codeが画像分析・ワイヤーフレーム・設計の内容から4手順の専用教材を作成し、保存・表示まで一周させて検証しました。

- 対象範囲：ヘッダー（ロゴ＋ナビゲーション）とファーストビュー（ヒーロー）のみ。LP全体ではありません。
- 手順1でHTML骨組みとフォルダ構成・`<link>`によるHTML/CSS接続を説明し、手順2〜4でstyle.cssを積み上げます（土台とヘッダー→ヒーローの横並び→文字とボタンと写真プレースホルダー）。
- 写真素材は未登録のため、`.hero__photo-placeholder`という点線枠のプレースホルダーで代用し、完成イメージ画像を背景に貼って再現したことにはしていません。
- 画像分析・ワイヤーフレームの作成日時を教材側に記録し、どちらかが更新されると「見直しをおすすめします」という案内を表示します。

### 相談欄の未確認・既知の制限

- 参考画像（複数・範囲指定あり）は今回は相談に添付していません。添付対象は完成イメージ画像のみです。
- 利用上限（レート制限）に達した場合の案内文言は、実際に上限へ到達させての確認はできていません（CLIが出力する`rate_limit_info`の状態値を見て判定するようにしていますが、実際に制限状態になったときの表示内容は未確認です）。
- 未ログイン状態での案内文言も、実際にログアウトさせての確認はできていません（stderr等のパターン一致による判定のため、CLIのバージョンが変わると文言が変わり判定が外れる可能性があります）。
- タイムアウト（2分）は実際に発生させての確認はしていません。

### 画像分析（Gemini API）の未確認・既知の制限

- 分析対象は完成イメージ画像のみです。参考画像（複数・範囲指定あり）はGemini APIへの自動分析には含めていません。
- 「既存の分析を上書きしてよいか」の確認は、ブラウザの`window.confirm`で行っています（②ワイヤーフレーム再生成時の確認と同じ方式）。自動操作環境の制約で、この確認ダイアログ自体の自動クリック操作は検証していません（ロジックはコードレビューと、確認なしで保存に進む分岐の動作で検証）。今回の実機確認では、分析対象のプロジェクトに既存の分析がなかったため、上書き確認が実際に表示される場面には遭遇していません。
- 利用上限（レート制限）は、実際に発生させての確認はしていません。無効なAPIキーについては実際にGoogle側のエラー形式を確認済みです。タイムアウト（180秒）については、延長前の60秒で実際にタイムアウトが発生することを確認済みです。
- モデル名は`server/.env`の`GEMINI_MODEL`でのみ変更可能です（アプリ画面上の設定項目は今回用意していません）。
- 相談欄が参照するのは「確定済み」の画像分析のみ。未確定の時点では相談に反映されません（詳細は下記「実際のGemini APIキーによる確認」）。

## AI API（画像分析）の接続方針

画像分析は2つの方式を併用できます。

1. **Gemini API（自動・要APIキー設定）**：「画像分析」タブの「画像を分析する」ボタンから、サーバーが登録済みの完成イメージ画像をGemini APIへ送信し、構成・配置・配色・文字の傾向・HTML/CSSの組み立て方針を自動で読み取って保存します。無料枠（クレジットカード登録不要）で利用可能です。APIキーはサーバー側（`server/.env`）のみで使用し、ブラウザ・ログ・Gitには出力されません。使用モデルは`GEMINI_MODEL`で変更できます（省略時は`gemini-3.8-flash`。画像入力に対応したモデルを指定してください。公式モデル一覧: https://ai.google.dev/gemini-api/docs/models ）。
2. **Claude Codeによる手動分析（従来どおり・APIキー不要）**：Claude Codeセッション自身が画像を直接読み取り、依頼のたびに分析結果を保存します。

どちらの方式で保存した結果も、同じ「画像分析」データとして扱われ、②ワイヤーフレームの「画像分析の結果から生成する」や、相談欄・教材作成から参照できます。既存の設計・ワイヤーフレームを自動で書き換えることはありません（分析結果の保存のみ行い、再生成は利用者の操作が必要です）。

Gemini APIの利用にあたっては、読み取れた事実と推定を区別するよう指示しており（元のCSS・正確なフォント名・正確な余白数値・レスポンシブ対応・アニメーションなどは断定しない）、保存後は内容をご確認のうえ必要に応じて修正してください。
